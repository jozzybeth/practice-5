# RAG Question Answering

Пайплайн для построения, тестирования и валидации системы Retrieval-Augmented Generation (RAG) по базе знаний компании с использованием гибридного поиска и автооценки результатов.

---

## 1. EDA

Цель проекта — построить и оценить систему ответов на корпоративные вопросы, исключающую галлюцинации и опирающуюся строго на регламенты компании.

В качестве датасета используются следующие данные:
* **Статьи (`articles.json`)**: 10 документов внутренней базы знаний.
* **Вопросы (`questions.json`)**: 50 тестовых вопросов без пропусков.
* **Эталонные ответы (`ground_truth.json`)**: 50 размеченных экспертных ответов.

---

## 2. Проделанная работа

1. **Эксперимент с Baseline (без RAG):** На первом этапе проведено тестирование моделей (Qwen 3.8 27B через Groq API и Llama 3.2 3B через vLLM) в режиме прямых ответов на вопросы без доступа к базе знаний, чтобы зафиксировать уровень "галлюцинаций".
2. **Построение RAG-пайплайна (Hybrid Retrieval):**
   * **Dense Retriever:** Векторный поиск в Qdrant с использованием эмбеддингов `BAAI/bge-m3`. Индекс сохраняется локально на диск в `models/qdrant_db/` для ускорения повторного инференса.
   * **Sparse Retriever:** Полнотекстовый поиск по ключевым словам на базе `BM25Retriever`.
   * **Ensemble Retriever:** Объединение плотного и разреженного поиска с взвешенным ранжированием контекстов перед передачей в LLM.
3. **Оценка качества:**
   * **Классическая:** Расчет метрик BLEU, ROUGE-1, ROUGE-2, ROUGE-L.
   * **LLM-as-a-Judge:** Автоматическая оценка смысловой корректности ответов моделью-судьей по 3-балльной шкале (0 — неверно, 1 — частично верно, 2 — полностью верно).

---

## 3. Результаты

### 1. Baseline (Ответы моделей без контекста)

Без доступа к внутренней базе знаний модели не способны угадать корпоративные регламенты и дают низкие показатели.

| Модель | BLEU | ROUGE-1 | ROUGE-2 | ROUGE-L | LLM-as-a-Judge (0–2) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Qwen 3.8 27B (Groq)** | 0.57 | 0.1025 | 0.0202 | 0.1025 | 0.200 |
| **Llama 3.2 3B Instruct** | 0.93 | 0.1323 | 0.0407 | 0.1323 | 0.040 |

### 2. RAG

Подключение RAG-пайплайна поднимает точность ответов. Модель `Qwen` с RAG достигает идеальной смысловой точности **2.000** по оценке LLM-Судьи.

| Модель | BLEU | ROUGE-1 | ROUGE-2 | ROUGE-L | LLM-as-a-Judge (0–2) |
| :--- | :---: | :---: | :---: | :---: | :---: |
| **Qwen 3.8 27B (Groq)** | **34.61** | **0.8628** | **0.4861** | **0.8548** | **2.000** |
| **Llama 3.2 3B Instruct** | 33.32 | 0.6900 | 0.2738 | 0.6713 | 1.700 |

---
## 4. Выводы
- Эксперимент показал, что без RAG модели плохо отвечают на вопросы, требующие специфической информации из корпоративной базы. При этом добавление внешнего контекста существенно повышает качество ответов.
- Среди протестированных моделей Qwen 3.8 27B показала лучшие результаты в RAG-сценарии. Она превзошла Llama 3.2 3B по BLEU, ROUGE-1, ROUGE-2 и ROUGE-L, а также получила более высокую оценку LLM-as-a-Judge. Это показывает, что более крупная модель эффективнее использует предоставленный контекст и лучше формулирует ответы на вопросы по корпоративным данным.

## 5. Инструкция по запуску через CLI

### 1. Подготовка окружения

pip install -r requirements.txt  

### 2. Для работы GROQ API

export GROQ_API_KEY="your_groq_api_key_here"  

### 3. Генерация baseline через Groq и VLLM
python -m scripts.main run-baseline --generator groq  
python -m scripts.main run-baseline --generator vllm  

### 4. Метрики для Baseline и RAG
python -m scripts.main eval-classical --target baseline    
python -m scripts.main eval-classical --target rag  

### 5. Оценка Baseline и RAG ответов
python -m scripts.main eval-judge --target baseline  
python -m scripts.main eval-judge --target rag
